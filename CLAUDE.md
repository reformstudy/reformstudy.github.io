# Claude Instructions for reformstudy.github.io

## Project Identity
**reformstudy.github.io** is a React + TypeScript web application for the ReformStudy platform—a digital study tool for biblical and theological research. The application is deployed as a GitHub Pages site with automated CI/CD via GitHub Actions.

## Technology Stack & Tooling
- **Runtime**: Node.js (ES modules)
- **Frontend**: React 18 with TypeScript 5
- **Bundler**: Vite 5 (with React plugin)
- **Icons**: lucide-react
- **Hosting**: GitHub Pages (source: `main` branch, `/docs` folder)
- **Type Checking**: TypeScript compiler (part of build)

## Development Workflow
### Initial Setup
```bash
npm install
```

### Local Development
```bash
npm run dev
```
Starts Vite dev server with HMR. In dev mode, resources are fetched from `/docs/resources/`.

### Building
```bash
npm run build
```
- Runs TypeScript type checking via `tsc`
- Bundles the React app with Vite into `docs/`

### Build Resources Only
```bash
npm run build:resources
```
Processes `res/` source files → `docs/resources/`. Run this when you add or change resource JSON files.

### Download and Validate Content
```bash
npm run ingest:kjv            # KJV from GitHub → res/bibles/kjv/kjv.json
npm run ingest:bsb            # BSB from the Free Use Bible API → res/bibles/bsb/bsb.json
npm run ingest:gill -- --books MAT,ROM   # Gill → res/commentaries/gill/ ("all" for every book)
npm run validate:resources    # also runs inside every build; errors fail the build
npm test                      # converter and validation tests (node:test)
```
Bible and commentary text under `res/` is generated by `scripts/ingest/`; never edit it by hand. The BSB and Gill sources (bible.helloao.org) are blocked in some sandboxes, so the **Fetch sources** workflow (`.github/workflows/fetch-sources.yml`) downloads them: it runs on pull requests that change `scripts/ingest/**` and commits the data to that branch, and can be run by hand from the Actions tab.

### Convert Raw Text to Resource JSON
```bash
npm run convert:resources -- --type <bible|confession|commentary|strongs> --input <file> --id <id> --name "Name"
```

### Preview
```bash
npm run preview
```
Serves the built `docs/` folder to verify production output.

## Resource System

The resource system is the core data layer. Resources (Bible, confessions, commentaries, Strong's concordances) are large JSON files served statically from `docs/resources/` and fetched on demand.

### How to Access Resources in Components
**Always use the `useResources()` hook** — do not import from `resourceLoader.ts` directly in components:

```typescript
import { useResources } from '../context/ResourceContext';

function MyComponent() {
  const { defaultBibleId, bibleIndexes, bibleBooks, ensureBibleIndex, ensureBibleBook,
          confessions, ensureResourceLoaded } = useResources();

  // Reading: load the book list, then only the book on screen.
  useEffect(() => { if (defaultBibleId) ensureBibleIndex(defaultBibleId); }, [defaultBibleId, ensureBibleIndex]);
  useEffect(() => { if (defaultBibleId) ensureBibleBook(defaultBibleId, 'ROM'); }, [defaultBibleId, ensureBibleBook]);
  const romans = defaultBibleId ? bibleBooks[`${defaultBibleId}/ROM`] : undefined; // undefined until loaded

  useEffect(() => {
    ensureResourceLoaded('wcf');          // Westminster Confession of Faith
    ensureResourceLoaded('strongs-greek');
  }, [ensureResourceLoaded]);
}
```

All `ensure*` functions are stable (safe in effect dependency lists) and idempotent: each file is downloaded once, and concurrent calls share the request. Only load a whole translation with `ensureResourceLoaded(bibleId)` when you need every verse (search does); it is 5+ MB.

### ResourceContext API (`src/context/ResourceContext.tsx`)
```typescript
interface ResourceContextType {
  manifest: ResourceManifest | null;
  bibles: Record<string, BibleVersion>;       // keyed by id, e.g. 'kjv'
  confessions: Record<string, Confession>;    // keyed by id, e.g. 'wcf'
  commentaries: Record<string, Commentary>;   // keyed by id, e.g. 'matthew-gill'
  strongsGreek: StrongsConcordance | null;
  strongsHebrew: StrongsConcordance | null;
  bibleIndexes: Record<string, BibleIndex>;   // book lists without text, keyed by translation id
  bibleBooks: Record<string, BibleBook>;      // single books, keyed `${translationId}/${bookId}`
  defaultBibleId: string | null;              // from manifest.defaultBible ('bsb' when present, else 'kjv')
  isLoading: boolean;                         // true while manifest loads
  error: Error | null;
  loadedResources: Set<string>;
  ensureResourceLoaded: (resourceId: string) => Promise<void>;
  ensureBibleIndex: (bibleId: string) => Promise<void>;
  ensureBibleBook: (bibleId: string, bookId: string) => Promise<void>;
}
```

The manifest is fetched on app init. Individual resources are lazy-loaded and cached in context state. `isLoading` reflects manifest initialization only — check that the specific resource (e.g. `bibleBooks['kjv/ROM']`) is truthy before rendering content.

### Resource Types and IDs
| Type        | IDs available            | Context key       |
|-------------|--------------------------|-------------------|
| Bible       | `'bsb'` (default, once downloaded), `'kjv'` | `bibleIndexes` / `bibleBooks` (per book), `bibles` (whole text) |
| Confession  | `'wcf'`                  | `confessions`     |
| Commentary  | `'matthew-gill'` (placeholder; not Gill's text) | `commentaries` |
| Commentary (chaptered) | `'gill'` (in the manifest; reader support comes next) | — |
| Strong's    | `'strongs-greek'`, `'strongs-hebrew'` | `strongsGreek`, `strongsHebrew` |

### Bible Book IDs
Bible books use USFM IDs (e.g. `'GEN'`, `'SNG'`, `'NAM'`, `'1JN'`, `'REV'`), listed in `scripts/lib/canon.js`. Testament values are `'OT'` or `'NT'`. Example:
```typescript
const book = bibleBooks['kjv/MAT'];
const verses = book?.verses.filter(v => v.chapter === 1) ?? [];
```

For advanced or non-component usage (scripts, utilities), `resourceManager` from `resourceLoader.ts` provides `loadBible(id)`, `loadConfession(id)`, `getVerse()`, `getChapter()`, etc. See `RESOURCES.md` for full type definitions and data formats.

## Key Architectural Patterns
- **`App.tsx`** wraps everything in `<ResourceProvider>` then renders `<AppContent>` which manages active module state
- **`useResources()`** is the only way components should read resource data
- **`ensureResourceLoaded(id)`** is idempotent — safe to call multiple times; does nothing if already loaded
- **`AtlasAndTimeline`** contains hardcoded `eraEvents` data; several eras have empty `events: []` (stubs)
- **Resource validation** (`scripts/validate-resources.js`) runs in every build. The KJV is the reference versification (exactly 31,102 verses); other translations are compared with it and differences are listed as warnings.

## Build & Deployment Pipeline
- **Source Control**: `main` branch
- **Automation**: GitHub Actions (`.github/workflows/deploy.yml`)
- **Build Output**: `docs/` directory
- **Hosting**: GitHub Pages (configured to serve `/docs` from `main`)
- **Process**: Commits to `main` → GH Actions builds → outputs to `docs/` → auto-deployed

- **Vite Base Path**: Set to `/` (root domain)
- **Build Output**: `docs/` (required for GitHub Pages)
- **React Plugin**: `@vitejs/plugin-react` with TSX support
- **Resource URL in dev**: `/docs/resources/` — in production: `/resources/`
- **No Environment Files**: Standard Vite setup (can add `.env` if needed)

## Code Standards & Patterns
1. **Components**: Functional components only, use TypeScript for all props
2. **File Naming**: PascalCase for `.tsx` files (e.g., `ScriptureReader.tsx`)
3. **Module System**: ES6 `import/export`
4. **Styling**: CSS custom properties from `styles.css`; component-level via inline styles or `className`
5. **Type Safety**: Define all prop types; avoid `any`
6. **Icons**: lucide-react only
7. **Resources**: Access via `useResources()` hook, not raw `resourceLoader.ts` imports

## Common Scenarios

### Adding a New Module
1. Create `src/components/MyModule.tsx` with TypeScript prop types
2. Use `useResources()` to access data and call the matching `ensure*` function
3. In `App.tsx`, add a `navItems` entry and a `<Route>` for it
4. Add global styles to `styles.css` using existing CSS custom properties

### Accessing Bible Data
```typescript
const { bibleBooks, ensureBibleBook } = useResources();
useEffect(() => { ensureBibleBook('kjv', 'GEN'); }, [ensureBibleBook]);
const book = bibleBooks['kjv/GEN'];
if (!book) return <LoadingState />;
const chapter1 = book.verses.filter(v => v.chapter === 1);
```

### Adding a New Resource
1. For downloaded text, add an ingest script in `scripts/ingest/` (pure convert function + CLI, with a fixture test in `scripts/tests/`). Otherwise add the JSON file to the appropriate `res/` subdirectory following the format in `RESOURCES.md`
2. Run `npm run build:resources` (validates, then publishes to `docs/resources/`)
3. Bibles, confessions and single-file commentaries are found through the manifest automatically; other types need a branch in `ensureResourceLoaded` in `ResourceContext.tsx`
4. Access it via `useResources()` in components

### Fixing Type Errors
- Run `npm run build` to see all TypeScript errors
- Check `tsconfig.json` for strict settings
- Ensure all prop types are explicitly defined
